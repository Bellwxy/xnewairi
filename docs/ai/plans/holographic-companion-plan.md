# AIRI 透明展示盒摆件开发规划

日期：2026-10-13。源码基线：`74e67fb`。状态：提案，尚未实施。

目标是透明展示盒。角色看起来悬浮在盒内，并能与用户对话。
计算位置尚未确定。本规划比较电脑、联网设备和全离线设备。

首选路线是先验证光学效果，再验证对话，最后集成独立主板。
第一版使用现有电脑、隐藏屏幕和透明反射片。不先开发完整硬件操作系统。

## 一 项目定位与复用范围

AIRI 是多端角色应用，不是现成的机器人固件。
它包含角色显示、对话编排、语音输入输出、模型供应商接入和扩展通道。
云端账户服务与扩展通道分别承担不同职责。

| 层次 | 现有模块 | 对摆件的作用 |
| --- | --- | --- |
| Web 宿主 | `apps/stage-web` | 电脑浏览器和 Linux 全屏显示的起点 |
| 移动宿主 | `apps/stage-pocket` | Android 主板或手机原型的起点 |
| 桌面宿主 | `apps/stage-tamagotchi` | 电脑原型、原生服务和现有桌面工具 |
| 共享应用层 | `packages/stage-ui` | 角色卡、会话、语音状态、配置与应用适配 |
| 对话核心 | `packages/core-agent` | 对话调度、上下文、工具轮次、VoiceController |
| 推理接入 | `packages/provider-inference` | 运行时中立的供应商定义与实例创建 |
| 音频基础 | `packages/audio`、`packages/pipelines-audio` | 浏览器音频适配、PCM、采集、播放与中断 |
| 角色显示 | `stage-ui-live2d`、`stage-ui-three` | Live2D 与 VRM 显示 |
| 其他显示 | `stage-ui-tachie`、`stage-ui-spine`、`stage-ui-mmd` | 静态表情、Spine 和 MMD |
| 口型驱动 | `packages/model-driver-lipsync` | 共享口型策略，各渲染器负责模型映射 |
| 扩展通信 | `server-runtime`、`server-sdk`、`plugin-protocol` | 事件转发、连接生命周期和协议契约 |
| 托管后端 | `server/apps/api`、`server/apps/auth` | 资源、账户和云端业务，不是摆件必装依赖 |
| 外部能力 | `services/`、`plugins/`、工具适配 | 以后接入传感器与受限设备操作 |

依据：[项目指南](../../../AGENTS.md)、[核心说明](../../../packages/core-agent/README.md)、[供应商说明](../../../packages/provider-inference/README.md)、[后端说明](../../../server/README.md)。

### 已经存在的基础

- `WidgetStage` 已整合多个角色渲染器。它还连接语音和应用状态，不是纯显示组件。
- `core-agent` 已抽出对话编排。无界面宿主不必重新编写全部对话逻辑。
- `VoiceController` 已提供输入、输出和指定轮次的中断生命周期。
- 共享语音已有常开、按键和唤醒词模式。不同宿主的触发能力不同。
- VRM 场景已有渲染比例和帧率配置。Live2D 也已有对应配置。
- Pocket 已有原生 WebSocket 桥接。SDK 负责重连、心跳、认证和连接状态。

依据：[Stage](../../../packages/stage-ui/src/components/scenes/Stage.vue)、[ThreeScene](../../../packages/stage-ui-three/src/components/ThreeScene.vue)、[语音集成](../../../packages/stage-ui/README.md)、[Pocket](../../../apps/stage-pocket/README.md)。

### 不能视为完成的能力

- WebSocket 事件通道不是完整语音媒体通道，也不是对话推理引擎。
- 当前 Stage context bridge 只发现文本输入处理。已定义的语音事件不能直接视为可用链路。
- 聊天附件读取不等于助手 TTS 音频下发。远程播放仍需明确的输出契约。
- 独立无界面对话宿主仍需会话持久化、角色配置、音频适配和服务生命周期。
- 现有云端聊天同步不等于角色、音频、模型资源和完整记忆同步。
- 唤醒词在桌面上的实现，不代表目标主板已经达到远场识别要求。
- 浏览器回声消除选项，不等于盒体、麦克风和扬声器已经完成声学调试。
- Kirie 的生产打包仍处于延期状态。本原型不把它作为必需条件。
- Home Assistant 的现有应用集成以 Electron 为范围，不能直接承诺 Pocket 或 Web 可用。

依据：[协议调研](../research/hardware-protocol-research.md)、[核心与同步边界](../../../packages/core-agent/README.md)、[唤醒词 ADR](../adr/2026-10-12-detect-wake-words-in-unprocessed-audio.md)、[Kirie](../../../apps/stage-tamagotchi-kirie/README.md)、[Home Assistant ADR](../adr/2026-10-06-home-assistant-integration.md)。

## 二 显示方案

推荐以 Pepper's Ghost 反射成像为基线。
隐藏屏幕显示黑底角色，斜放的透明反射片把图像反射给观看者。
这不是空气中的实体图像，也不是可绕行观看的真正体积全息。
即使源内容是 VRM，单视图反射仍不提供真实的多视角立体信息。

反射原理可参考[爱荷华大学物理演示](https://instructional-resources.physics.uiowa.edu/6a1060-mirrors-candle-under-water-and-peppers-ghost)。以下结构是原型建议，不是制造图。

```text
隐藏屏幕，位于盒顶或底座
             |
             | 发光
             v
       透明斜置反射片 ------> 正面观看者
             |
     暗色内腔与虚像空间
             |
底座：音频、按键、电源、可选主板
```

屏幕与反射片的角度从约 45 度开始试验。
最终角度、屏幕方向和图像翻转由实际光路决定。
用带方向标记的测试图校准，不能固定假设只需水平翻转。

| 方案 | 优点 | 代价 | 本轮选择 |
| --- | --- | --- | --- |
| 单面透明展示盒 | 单视图即可，能复用 AIRI 渲染 | 受环境光、观察位置和反射片质量影响 | 首选 |
| 四面透明棱锥 | 多方向可见 | 占用屏幕面积，需要多方向内容布局 | 不进入第一版 |
| 裸眼光场屏 | 能提供多视角立体显示 | 专用显示设备、SDK 和更高渲染负载 | 独立产品路线 |

[Looking Glass 官方说明](https://lookingglassfactory.com/webxr)要求网页接入其 WebXR 库，并使用配套 Bridge。它不是普通 HDMI 显示器的无修改替代品。

### 光学与外壳要求

- 使用真黑画面。禁止把聊天面板、菜单、默认背景或加载白屏投射进展示区。
- 先使用现有 OLED 手机验证黑位。后续比较 OLED 与 LCD 实物，不能只比较标称亮度。
- 普通透明片用于概念验证。成品样机比较分光片、表面反射、重影和划痕。
- 前方保留透明视窗。后方和侧方允许遮光，避免要求所有方向完全透明。
- 第一轮比较 5 至 7 英寸屏幕样件。角色有效尺寸由光路决定，不等于屏幕对角线。
- 采用可调支架。先确定视线高度、观看距离和角色脚部位置，再固定外壳尺寸。
- 采用 USB 或 HDMI 成品接口。第一版不做裸屏驱动板和自制市电电路。
- 把麦克风置于盒外声学开口。隔离扬声器振动、风扇气流和电源噪声。
- 长时间运行必须检查温升。OLED 还需亮度管理、定时熄屏和静态内容老化评估。

以上是工程试验要求。亮度、可视角、散热和使用寿命仍需实物验证。

## 三 计算位置选择

显示宿主、对话编排和模型推理是三个位置选择，不是一个选择。
例如，树莓派可以运行显示与编排，同时调用家中电脑上的模型服务。
这种结构不需要先把全部编排迁移为远程服务。

| 路线 | 显示与编排 | 模型推理 | 成本和体验 | 建议 |
| --- | --- | --- | --- | --- |
| 电脑直连 | 现有电脑，HDMI 屏幕与 USB 音频 | 云端或现有本地服务 | 新增软件最少，需要电脑常开 | 第一台原型 |
| 联网独立摆件 | Linux 主板或 Android 设备 | 云端服务 | 盒内算力要求较低，有调用费和网络依赖 | 第二阶段候选 |
| 家庭本地混合 | 盒内显示和音频，编排位置另定 | 家中电脑或服务器 | 数据能留在家中，需要主机与局域网 | 隐私优先候选 |
| 盒内全离线 | 盒内全部运行 | 盒内模型 | 模型、内存、热量和噪声压力最大 | 单独评估 |

“调用家中模型 API”与“通过 AIRI WebSocket 远控电脑”不是同一方案。
前者保留设备上的 AIRI 编排。后者还需远程语音、会话和播放控制适配。

### 主板选择顺序

| 候选 | AIRI 起点 | 首要检查 | 不作出的承诺 |
| --- | --- | --- | --- |
| 现有电脑加屏幕 | `stage-web` 或现有桌面客户端 | 双屏、音频设备选择、全屏启动 | 不承诺便携 |
| 现有 Android 手机 | `stage-pocket` | WebView、麦克风权限、充电温升、屏幕方向 | 不承诺长期封闭充电安全 |
| 树莓派 5 | `stage-web` 加 Chromium 全屏宿主 | 实际 WebGL、WASM、音频驱动和温升 | 不承诺复杂 VRM 与本地模型同时流畅 |
| 香橙派或 RK 系主板 | Linux Web 或厂商 Android | 系统镜像、GPU 驱动、音频和维护周期 | 不把 NPU 标称算力当成 AIRI 已支持 |
| x86 小主机 | Web 或桌面客户端 | 体积、功耗、风扇和本地模型性能 | 不承诺所有模型都能低延迟运行 |

[Capacitor 官方支持 Android、iOS 和 Web](https://capacitorjs.com/docs/getting-started/environment-setup)。它不是把 Pocket 原生包直接安装到普通 Linux 的方案。
[树莓派官方](https://www.raspberrypi.com/products/raspberry-pi-5/)建议合适的 5V/5A 电源，并说明主动散热有利于性能。封闭盒体必须独立验证散热。

## 四 软件结构

### 第一阶段 不引入分布式系统

```text
USB 麦克风 -> AIRI 语音输入 -> 模型服务
                                  |
HDMI 屏幕 <- 本机角色显示 <- 回答与语音
USB 扬声器 <- 本机音频播放
```

在 `stage-web` 内增加独立展示入口，先复用 `stage-ui`。
展示入口与管理入口分开。管理入口继续复用现有配置组件。
角色区支持黑底、旋转、翻转、位置和缩放校准。
界面不在展示区显示聊天历史。错误详情在管理端显示。

第一版由同一 AIRI 宿主负责会话、采集和播放。
不额外制造一套角色状态或 TTS 管线。
`WidgetStage` 当前持有业务依赖。真正的远程纯显示端，需要以后明确抽出显示边界。

优先选一个已有、许可明确的 Live2D 角色。先减少模型和动画变量。
如果需要转身和立体动作，再比较轻量 VRM。静态 Tachie 用于光学测试，不承担口型功能。
两种动态模型都需测量，不能只凭格式判断性能。

Linux 浏览器从本机受信任入口或 HTTPS 加载页面。
麦克风权限、自动播放和开机恢复分别验收。不能用关闭浏览器安全机制代替部署方案。

### 第二阶段 独立设备与可选远程编排

```text
管理端 -- 配对、配置 --> 设备宿主
                         |
                本地显示、采集和播放
                         |
          本地 AIRI 编排 或 远程 AIRI 宿主
                         |
                  云端或本地模型服务
```

优先保留设备本地渲染。传输文本、状态和必要音频，不默认传输整段角色视频。
本地渲染能在模型服务断开时保留待机形象。
视频串流仅作为低渲染能力设备的候选，需单独比较带宽、延迟与音画同步。

### 代码落点提案

这些路径是未来提案，不表示已经创建。

| 提案位置 | 职责 | 建立条件 |
| --- | --- | --- |
| `apps/stage-web/src/pages/` 的展示入口 | Linux 与电脑展示模式 | 光学试验通过 |
| `packages/stage-ui/src/components/scenarios/` 的展示组件 | 共享校准与角色展示 | Web 和 Pocket 同时需要 |
| `apps/stage-pocket` 的宿主配置 | Android 常驻、屏幕方向、原生权限 | Android 路线通过测试 |
| `packages/plugin-protocol` | 集中定义新增 Eventa 契约 | 现有契约无法表达实际需求 |
| `services/airi-device-host` | 设备 I/O 与服务生命周期 | 浏览器确实需要访问原生设备 |
| `services/airi-companion-host` | 无界面对话宿主，复用 core-agent | 确定远程编排且现有宿主不够用 |
| `deploy/` 的设备配置 | 开机启动、日志限制、版本与恢复 | 独立设备阶段 |

共享显示逻辑放入 `packages/`。不复制整套 Pocket 或 Web 应用。
只在存在真实消费方时抽取新包。新增库先做候选比较，再由用户确认。

### 远程协议必须补齐的语义

- 设备身份与角色、会话、轮次身份分开。
- 音频明确编码、采样率、通道、序号和时间基准。
- 定义播放开始、播放结束、中断确认和失效轮次丢弃。
- 重连后读取当前状态。不重放已经结束的语音和设备动作。
- 同一输入只有一个编排负责人。同一轮回答只有一个指定播放设备。
- 接收成功与实际执行成功分开。控制动作需要执行结果。
- 配对令牌必须可撤销。生产部署使用加密链路和设备权限。
- 用 Eventa 定义跨进程契约。入口数据使用 Valibot 验证。

这些是新增产品要求。现有 SDK 的心跳与重连不能替代这些要求。
媒体方案先比较现有文本编码事件、独立二进制 WebSocket 和 WebRTC。
本轮不选择新库，不新增依赖声明。

## 五 语音与陪伴体验

第一版保留一个明确的开始对话动作和停止播放动作。
远场唤醒通过实物测试后，再设为默认入口。
Pocket 当前未声明硬件按键 PTT 触发器。底座按键需要宿主适配，不能只接一根 GPIO。
现有唤醒词检测使用未处理的第二路采集，自身播音造成的误唤醒必须单独测试。

推荐状态包括待机、监听、思考、说话、静音和离线。
状态变化使用角色动作和底座指示，不在展示区铺满提示文字。
离线时停止发送请求，保留待机显示，并明确提示无法回答。

第一版不加入摄像头、人脸识别、机械动作和主动控制家电。
这些功能分别增加隐私、误识别或物理操作风险。
后续设备动作必须经过权限、参数范围和执行确认，不能由模型文本直接驱动。

## 六 分阶段交付

时间是单人原型的工作量估算，不是交付承诺。不包含采购、加工和硬件返工等待。

| 阶段 | 估算 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| P0 光学验证 | 2 至 4 个工作日 | 手机或外接屏、可调反射片、黑底角色 | 常用桌面光照下能看清表情，尺寸和视线可接受 |
| P1 AIRI 直连原型 | 5 至 10 个工作日 | 展示模式、校准、USB 音频、完整一轮对话 | 显示不露出管理 UI，语音和口型可用 |
| P2 独立宿主比较 | 5 至 10 个工作日 | 至少两类宿主的同场景测试表 | 帧率、延迟、温升和预算满足约定目标 |
| P3 常驻设备样机 | 10 至 20 个工作日 | 开机恢复、配对、断网恢复、物理静音 | 通过 24 小时常驻和多次断网测试 |
| P4 小批量准备 | 另行估算 | 定版结构、生产测试、升级回滚、许可清单 | 通过寿命、安全和目标市场要求检查 |

若 P0 观感不合格，先调整反射片、屏幕和遮光。不要用模型升级补偿光学问题。
若 P2 主板不满足性能，先降低渲染负载或外移推理。不要直接承诺换一个小模型即可解决。

## 七 验收指标草案

以下数字是测试目标，不是本仓库或硬件的已测结果。
固定角色模型、分辨率、音量、光照、网络和供应商，再比较设备。

| 项目 | 初始目标 | 测量方式 |
| --- | --- | --- |
| 显示 | 目标 30 FPS，连续 30 分钟无持续降频 | 记录帧时间分布、CPU、GPU 和温度 |
| 首次语音 | 从用户说完到首段可听音频，P50 不超过 2.5 秒，P95 不超过 5 秒 | 分别记录端点判断、ASR、LLM、TTS 与播放 |
| 停止播放 | 指令到实际静音不超过 300 毫秒 | 录音测量，不以 UI 状态变化代替 |
| 口型 | 音画偏差目标不超过 150 毫秒 | 同步拍摄屏幕与音频 |
| 唤醒 | 首轮 100 次呼叫命中至少 90 次，8 小时背景测试误唤醒不超过 1 次 | 覆盖距离、说话人和设备自身播放 |
| 恢复 | 网络恢复后 10 秒内回到可用状态，不播放旧回答 | 断开网络、重启模型服务、重启设备 |
| 常驻 | 24 小时无崩溃，无持续内存增长或温度超限 | 连续日志与周期采样 |
| 隐私 | 静音后不采集，默认不保存原始录音 | 分别检查物理状态、权限和数据路径 |

光学验收使用目标桌面位置，不只在暗室拍摄效果图。
开机时间在资源下载完成后测量。首次下载另外计时。
测试未通过前，不公布远场、离线或无人值守能力。

## 八 成本框架

本节是研发预算建议，不是零售报价。币种为人民币。
预算不含已有电脑、人工、运费、税费、云端调用和模具。
采购前必须按屏幕与板卡具体型号重新询价。

## 九 安全与维护

- 屏幕失联时维持安全的静音状态。不要无限重试播放。
- 配对凭据不写入前端源码、镜像或公开日志。
- 出厂使用独立设备凭据。禁止全批次共用一个永久令牌。
- 物理静音必须真正切断或禁用采集路径，不能只有屏幕图标。
- 更新包验证来源。失败时回滚到已知可启动版本。
- 给日志和缓存设置上限。长期开机不能持续写满存储。
- 原型使用认证成品电源。定版前检查散热、材料、边缘和电气安全。
- 商用前核对模型、动作、声音、字体和 SDK 许可。仓库 MIT 不覆盖全部资源。

## 十 下一步决策

下一步先确定三个产品参数：整机预算、角色可见高度、通常观看距离。
随后选择一个现有角色和一个现有屏幕，执行 P0。
P0 通过后，再为展示入口编写实现 ADR 和验收清单。

当前不采购主板，不开发云端账户系统，不引入新的渲染引擎。
这三个决定都依赖光学样机和用户实际体验。
